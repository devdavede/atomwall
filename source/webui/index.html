Overview

Sites

Additional domains layered on top of the default site below. A request's Host header (HTTP) / TLS SNI name (HTTPS) is matched by exact, case-insensitive equality against a site's domain and routed to that site's own upstream and certificate. Blacklists, ban & scoring, response pages, etc. stay global and apply to every site. Disabling a site 403s it without deleting its config.

Live Globe

Every allowed (green) or blocked (red) request drawn as an arc from the visitor's approximate city to this server's location. The underlying event only ever carries a rounded lat/lon and allow/block — never an IP, so this view (and the public embed below) can never show a visitor's identity.

Whitelist

Exact IPs or CIDR ranges, IPv4 or IPv6. A whitelisted IP bypasses every check — the temporary/auto-ban gate, every blacklist, speed check, and method allowlist — no matter what it does. Always permanent; there's no time-limited whitelist entry, and nothing here auto-expires.

IP / CIDR blacklist

Exact IPs or CIDR ranges, IPv4 or IPv6. Manual blocks can be permanent or time-limited; score-triggered blocks (see Ban & scoring) always show up here too, tagged auto.

Blocked routes

Case-insensitive substring match against the request path (query string excluded), e.g. /wp-admin blocks that path and anything under it.

RouteSourceAddedExpires

Fake routes honeypot

Paths that don't exist and are never linked from real content. As soon as one is added here it's advertised as a Disallow entry in /robots.txt — a well-behaved crawler will never request it. Anything that requests one anyway is blocked and scored (score name fake_route, see Ban & scoring below) as a strong signal, not a normal route match. Must start with /; prefix-matched, same as robots.txt's own Disallow semantics.

Ban & scoring

Each blocked request adds its check's score to that IP. Crossing the threshold blocks the IP for the ban duration (shows up in IP / CIDR above, tagged auto) and resets its score to zero.

Points per check

Speed check

Flags a client IP navigating too fast: more than the configured number of requests within a sliding time window. An over-limit request is scored and blocked (score name speed_check, see Ban & scoring above) the same way as every other check.

Limits

Soft body-size limit — distinct from the hard safety cap that protects against unbounded allocation. Exceeding this scores + returns a clean 403 instead of aborting the connection. 0 disables it.

Response pages

Shown to clients on a block. Leave blank to use the built-in default. “Blocked” is used for rule matches (blacklists, size limit); “Banned” is used specifically for temporary/score-triggered IP blocks.

Status code pages

Custom HTML for specific origin response status codes (e.g. 404, 503). Applies when the upstream's response carries that status — only the page body is replaced, the status code itself always still comes from the origin.
